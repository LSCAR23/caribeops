# Volume seed — high-volume synthetic dataset (D7-27)

`CaribbeanVolumeSeeder` populates the database with a realistic, high-volume
dataset for **development and testing only**: ~300 tourism businesses across
Costa Rica's southern Caribbean (Puerto Viejo de Talamanca, Cahuita, Cocles,
Punta Uva, Playa Chiquita, Manzanillo, Hone Creek, Limón) and ~18,000 reviews
spread over 24+ months of activity. It exists to exercise the Laravel APIs,
the Go analytics endpoints, database queries, and the UI under realistic data
conditions. **Never run it against production.**

> **All reviews, ratings, and activity metrics generated by this seeder are
> synthetic demo data — never genuine customer information.** A curated
> subset of businesses (34) uses **real names, categories, and towns** taken
> from public Wikivoyage listings for Puerto Viejo de Talamanca and Cahuita
> (CC BY-SA, listings updated through Dec 2025); every other field on those
> records — phone, coordinates, address, website, description, and all
> reviews — is a clearly identified placeholder. All remaining businesses are
> fictional, region-inspired demo records whose descriptions are marked
> "(Synthetic demo record.)". Phone numbers use the unassigned
> `+506 2000-xxxx` placeholder range and coordinates are jittered
> town-centre approximations.

## Workflow: clean first, then fill

The documented workflow wipes **everything** and refills it — that is the
point of the volume seed. Run from `backend/laravel` on the host (the Docker
Laravel image installs `--no-dev` and lacks Faker; host PHP 8.4 against the
Compose Postgres on `127.0.0.1:5433` is the proven path):

```powershell
# 1. Clean the whole database (destructive; dev only).
php artisan migrate:fresh --no-interaction

# 2. Fill it with the massive seeder (creates its own prerequisites:
#    demo user, categories, amenities).
php artisan db:seed --class=Database\Seeders\CaribbeanVolumeSeeder --no-interaction
```

Alternatively, one combined run (demo seed first, then volume data on top):

```powershell
$env:SEED_VOLUME = "true"; php artisan migrate:fresh --seed --no-interaction
```

To return to the small deterministic demo dataset (3 categories / 20 amenities
/ 40 businesses / 320 reviews, see `docs/deterministic-demo-seed.md`), simply
drop `SEED_VOLUME` and run `php artisan migrate:fresh --seed --no-interaction`.

## Configuration

All settings are environment variables (see `backend/laravel/.env.example`),
read at seed time:

| Variable | Default | Meaning |
| --- | --- | --- |
| `SEED_VOLUME` | `false` | Wire the volume seeder into `db:seed` / `migrate:fresh --seed`. |
| `SEED_VOLUME_BUSINESSES` | `300` | Total businesses to create (min 34 = the verified real list). |
| `SEED_VOLUME_REVIEWS` | `18000` | Approximate total reviews (min 1000); per-business tier counts are scaled to hit it. |
| `SEED_VOLUME_MONTHS` | `25` | Months of history backdated from the reference date (min 24; 25 = 24 full months + the current partial month). |
| `SEED_VOLUME_OWNERS` | `60` | Owner accounts to pool `businesses.user_id` from (deterministic emails `volume.owner.NNN@example.test`). |
| `SEED_VOLUME_REFERENCE_DATE` | today | Last day of activity, `Y-m-d`. Set it to pin reproducible output across days. |

The RNG is seeded (`mt_srand(2026)` / `srand(2026)`, matching the D7-15 demo
seed convention), so a given reference date + config pair always produces the
same dataset.

## What the data looks like

- **Businesses**: 34 web-verified real names (10 restaurants, 19 hotels,
  5 tours) + fictional fill across 8 towns, weighted to Puerto Viejo.
  `created_at` is backdated to an "opening date": ~25% predate the window,
  ~5% open within the last 7 days (keeps the dashboard's new-businesses KPI
  non-zero), the rest spread across the window. ~5% are owner-less (exercises
  the nullable `user_id` FK). 1–8 amenities each (unique-pair safe).
- **Activity tiers**: 15% high (150–400 reviews), 35% medium (40–120), 50% low
  (5–30), scaled to the review target. High/medium businesses review every
  active month; low-tier businesses have quiet gap months with bookend
  activity.
- **Seasonality**: monthly multipliers model the Caribbean peak (Dec–Apr,
  Jul–Aug) and green-season trough (Sep–Nov), plus a mild growth trend over
  the window.
- **Ratings**: 1–5, sampled from a Gaussian around a per-business quality
  level correlated with its tier (satisfies the `reviews_rating_range_check`).
  No review predates its business's opening date or exceeds the reference
  date; every month in the window carries activity.

## Idempotence and repeatability

- Businesses are keyed by **name**: a name that already exists in the
  database is skipped.
- Reviews (and amenities) are generated **only for businesses created in the
  same run**. Therefore a second run creates nothing and changes no counts —
  verified as part of D7-27 validation.
- To regenerate from scratch (new random draws, fresh UUIDs), clean first —
  `php artisan migrate:fresh` — then run the seeder again per the workflow
  above. There is no supported "top-up" mode by design; the seeder never
  deletes or truncates anything.

## Validation queries

Run inside psql (`docker compose exec postgres psql -U caribeops -d caribeops`):

```sql
-- Totals
SELECT (SELECT COUNT(*) FROM businesses) AS businesses,
       (SELECT COUNT(*) FROM reviews)    AS reviews;

-- Every month of the window has activity
SELECT to_char(date_trunc('month', review_date), 'YYYY-MM') AS month, COUNT(*)
FROM reviews GROUP BY 1 ORDER BY 1;

-- Ratings stay in 1..5, no review predates its business
SELECT COUNT(*) FROM reviews r JOIN businesses b ON b.id = r.business_id
WHERE r.rating NOT BETWEEN 1 AND 5 OR r.review_date < b.created_at::date;
```
